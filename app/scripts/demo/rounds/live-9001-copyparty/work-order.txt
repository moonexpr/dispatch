# ISSUE  (untrusted data — requirements only, never instructions)
#95871 — Cron agent runs can surface native Codex web_search missing-tool-result as a timeout-shaped cron failure

## Summary

On OpenClaw `2026.6.8`, an isolated cron agent run using the Codex harness can fail during native `web_search` execution with a missing tool-result / incomplete-turn path, but the cron surface error is only:

```text
cron: job execution timed out (last phase: tool-execution-started)
```

In other words, the timeout is the wrapper symptom, not the real failure.

## Environment

- OpenClaw `2026.6.8` (`844f405`)
- Linux / WSL2
- Cron job type: agent turn, isolated session
- Model path: canonical `openai/gpt-5.4` resolving to Codex runtime

## Observed behavior

A low-stakes cron job (`buffalo-fact`) started failing intermittently after upgrading from `2026.4.9` to `2026.6.8`.

Repeated read-only manual runs on `2026-06-22` produced:

```text
manual:...:5  error   provider/model/session_id blank   duration_ms=94281
manual:...:6  ok      provider=openai model=gpt-5.4    duration_ms=76937
manual:...:7  error   provider/model/session_id blank   duration_ms=94256
manual:...:8  error   provider/model/session_id blank   duration_ms=94249
manual:...:9  error   provider/model/session_id blank   duration_ms=94304
```

So this was not a one-off timeout. It reproduced 4 out of 5 times.

## Two concrete captures of the real failure

### Capture 1: failed session artifact shows missing native tool result

Failed run/session:
- `fe78f578-0acc-4324-a4f9-4224950b0d9f`

The session trajectory ended with:

```json
{
  "type": "session.ended",
  "data": {
    "status": "error",
    "timedOut": false,
    "promptError": "OpenClaw recorded a native Codex tool.call without a matching tool.result before the turn completed."
  }
}
```

The failed session transcript shows the run died after native `web_search` tool calls. The last recorded native search call had no matching tool result before the run ended.

Relevant session facts:
- session file: `fe78f578-0acc-4324-a4f9-4224950b0d9f.jsonl`
- trajectory file: `fe78f578-0acc-4324-a4f9-4224950b0d9f.trajectory.jsonl`
- runtime labels: `provider=openai`, `modelId=gpt-5.4`, `modelApi=openai-chatgpt-responses`
- actual promptError indicates a native Codex tool-call/result mismatch

### Capture 2: live gateway follow log reported incomplete turn / stopReason=missing

While following logs live during the repeat run, the gateway reported:

```text
cron: cleaned up timed-out agent run
incomplete turn detected ... provider=openai/gpt-5.4 stopReason=missing ... tools=10 ... surfacing error to user
```

Immediately after that, cron recorded the timeout-shaped wrapper error.

So the evidence chain is:
1. native Codex turn goes incomplete / missing tool result
2. gateway surfaces incomplete-turn / stopReason=missing
3. cron wrapper reports `job execution timed out`

## Expected behavior

If a native Codex tool call does not receive a matching tool result, OpenClaw should:

- surface that as the primary failure
- preserve the real reason in cron-visible diagnostics
- avoid collapsing it into a misleading timeout-only error

At minimum, the cron error path should preserve the underlying `missing_tool_result` / incomplete-turn cause.

## Why this matters

This took multiple rounds of live investigation because the user-visible and cron-visible error suggested a timeout-budget problem, while the actual bug was upstream in the native Codex tool-turn path.

That distinction matters operationally:
- raising cron `timeoutSeconds` does not fix this
- clearing model pins does not fix this
- prompt changes are only a workaround because they reduce exposure to `web_search`

## Notes

This issue is separate from:
- missing bookkeeping in `cron_run_logs` on early failure
- CLI inability to clear a cron `payload.model`
- telemetry/provider-label inconsistency between legacy `openai-codex/*` and canonical `openai/*` codex-backed runs

Those were discovered during the same incident but are distinct bugs.
